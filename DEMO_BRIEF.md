# GigaMeter — Demo Brief

## Что это

JMeter-плагин, который добавляет AI-чат прямо в интерфейс JMeter.  
AI помогает писать тест-план с нуля, анализировать готовый план, переименовывать элементы и разбираться в JSR223-скриптах.

---

## Ключевые сценарии для демо

### 1. Генерация тест-плана `@plan`

**Что показать:**
- `@plan Нагрузочный тест: логин по логину/паролю, получение списка заказов, создание заказа`
- AI генерирует preview с Thread Group, HTTP Sampler-ами, Token Extractor, Assertion и Timer
- `@plan apply` — план вставляется в дерево JMeter одним действием
- `@rollback` — план удаляется, дерево возвращается к исходному состоянию

**Акцент:** нет ни одной ручной операции — от текста до рабочей структуры за несколько секунд.

---

### 2. Объяснение JSR223-скрипта `@this`

**Что показать:**
- Выбрать JSR223 Sampler или PreProcessor с нетривиальным Groovy-кодом
- `@this` — AI объясняет: что делает скрипт, какие JMeter-переменные читает/записывает, побочные эффекты, что может пойти не так
- `@this <вопрос>` — ответ на конкретный вопрос про код

**Акцент:** тест-инженеру не нужно читать Groovy — AI читает скрипт и объясняет человеческим языком.

---

### 3. Переименование элементов `@lint`

**Что показать:**
- Выбрать Thread Group с хаотичными именами
- `@lint` — AI переименовывает все элементы по единому стандарту (TG_, HTTP_10_GET_, JSR_, TC_, EXT_ и т.д.)
- `@rollback` — возврат к исходным именам

**Дополнительно:** `@lint используй snake_case, только английский` — AI подстраивается под пользовательский стиль.

---

### 4. Анализ существующего плана `@plan analyze`

**Что показать:**
- Открыть готовый `.jmx` файл
- `@plan analyze` — AI показывает: структуру, HTTP-эндпоинты, Thread Groups, и пишет бизнес-интерпретацию: что тестируется, какие риски покрыты, что пропущено

---

### 5. Контекстное меню в JSR223-редакторе

**Что показать:**
- Открыть JSR223 Sampler, выделить фрагмент кода
- Правая кнопка → **AI Refactor** — AI улучшает код
- Правая кнопка → **Wrap in try/catch/finally** — оборачивает в стандартный JMeter-шаблон

## Поддерживаемые AI-провайдеры

| Провайдер | Статус | Примечание |
|---|---|---|
| OpenAI (GPT-4o, GPT-4.1) | Полная поддержка | Лучшее качество ответов |
| Sber GigaChat | Полная поддержка | Российский провайдер, без зарубежных ключей |
| DeepSeek | Полная поддержка | Дешевле OpenAI, хорошее качество |

Модель и провайдер переключаются прямо в UI чата — без перезапуска JMeter.

---

## Текущие ограничения

| Ограничение | Детали |
|---|---|
| Размер плана для AI | Не более 300 элементов в одном запросе; очень большие планы обрезаются |
| `@code` не вставляет код в редактор | Ответ AI приходит только в чат; вставка вручную |
| GigaChat TLS | На некоторых Java-стендах нужна настройка truststore или `giga.ssl.insecure=true` |
| GigaChat reasoning | Нет нативного режима размышления — эмулируется через промпт |
| Usage-статистика DeepSeek | Не реализована |
| Тёмные темы JMeter | Возможны проблемы с видимостью элементов чат-панели |
| Откат (`@rollback`) | Только одна операция назад; каскадного undo нет |

## Быстрый старт для демо

```
# 1. Скачать JAR из nightly
https://github.com/system0shock/GigaMeter/releases/tag/nightly

# 2. Положить в JMETER_HOME/lib/ext

# 3. Добавить в user.properties (пример для GigaChat):
jmeter.ai.service.type=giga
giga.auth.key=<ваш ключ>
giga.default.model=GigaChat-2-Max

# 4. Запустить JMeter — в меню Options появится GigaMeter
```
